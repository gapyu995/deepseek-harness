# Agent Note: 工作区多选归档

Status: implemented

[English](2026-08-28-workspace-multi-select-archive.md) | 中文

## 问题

工作区浏览器通过行内省略号菜单的「归档」动作一次归档一个会话。清理大量会话意味着对每一行重复该手势，而浏览器没有选择界面。

## 决策

在现有的逐个会话归档动作之上增加客户端多选模式，而不拓宽工作区传输协议。

- 区头的 `Select` 操作进入多选模式：非空白会话行变成复选开关（`aria-selected` 反映勾选状态），区头切换为批量操作栏（`全选`／`归档`／`取消`），激活期间搜索、视图选项、添加、行内菜单与拖拽均被抑制。空白的新会话行绝不会进入选择集合（没有可归档的内容）。
- `全选` 勾选实时会话列表中所有非空白、未归档的会话 id。
- `归档` 按顺序提交已勾选集合——对每个 id 依次 `await archiveSession(id)`，而非 `Promise.all`——因为每次归档都是一次注册表读改写；并发提交可能各自回显缺少其他成员关系的集合。循环先退出多选模式，再逐个等待写入；失败与单行归档一样，仅作非致命的控制台诊断。

## 备选方案

- **批量 Host 端点（`workspace.archiveSessions`）**——一次 RPC 的原子提交，但会为低频的批量手势拓宽 API remotes 契约、Host 工作区服务与运行时工作区接口。顺序客户端循环已经正确：逐个会话的动作是幂等的，且每次响应都回显完整集合。
- **对选中 id 并发 `Promise.all`**——往返更少，但读改写竞态可能让最后一次回显丢失成员关系；顺序提交能保住集合。

## 后果

批量归档只是 `ui-workspace` 内的一处查看状态新增：不涉及服务、传输或持久化改动，因此远程浏览器与对象层不受影响。选择状态是组件局部的，退出时重置；进入多选模式会清除搜索查询，使两个界面互不混杂。代价：归档 N 个会话会发出 N 次顺序 RPC（对侧边栏规模的数量足够），且该模式仅在宽屏下可用——折叠轨道保留其既有的两个控件。
